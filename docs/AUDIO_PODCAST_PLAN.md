# THE DAILY NOISE — AI 播客第二阶段设计

状态：规划中，尚未接入 TTS 服务、生成音频或启用定时音频发布。

## 目标
在已有 25 篇来源可核验的每日新闻基础上，制作 10–15 分钟中文新闻音频节目。保留“逐篇朗读”作为免费、即时的独立模式。播客音频不得依赖浏览器持续前台运行。

## 内容管线
1. 从同一次生成任务的已验证 articles JSON（而非从 HTML 反向抓取）提取标题、摘要、背景、来源及发布日期。
2. 由 LLM 生成口语化播报稿：开场、重点排序、段落过渡、背景解释、结尾。禁止虚构引语、现场采访、未证实的数字及来源。
3. 验证稿件仅引用当期已有事实；保留可追溯的文章 ID 和来源链接。事实校验失败则不发布音频。
4. TTS 生成中文 MP3/M4A，优先单主持人；双主持人仅在语音质量和成本验证后启用。控制分段大小，失败可重试，避免重复计费。
5. 音频上传至适合媒体文件的存储（例如 Cloudflare R2）；GitHub 仓库只存节目元数据和播放清单，不提交大音频。
6. 生成节目 JSON、可下载音频地址和可选的 podcast RSS enclosure；页面用 HTMLAudioElement 提供时长、进度、倍速、后台/锁屏播放（实际行为需 iOS 真机验收）。
7. 在 CI 中加幂等保护：同一北京时间日期同一新闻版本只生成一次音频；音频失败不阻塞文字新闻发布。

## 技术与成本决策
先用相同的 2 分钟中文播报稿对候选 TTS（例如 Azure Speech、Google Cloud TTS、国内云语音服务）进行盲听对比，测量人民币成本/节目、语气自然度、数字和英文专名发音、可用地区、API 权限及版权许可。不得在未测试和取得密钥前声称已选择供应商。

## 页面设计
- audio.html 的「逐篇朗读」继续使用 Web Speech API，零服务器 TTS 成本。
- 「播客模式」在音频就绪前展示筹备说明，不显示虚假播放按钮或时长。
- 播客就绪后切换至原生 <audio controls> 作为可靠的基础播放控件，附完整播报稿、来源链接及下载按钮。
- 对生成日期、是否最新一期、TTS 服务异常和音频缺失提供明确状态。

## 验收
- iPhone Safari：点击播放、暂停、切换文章、语音选择、锁屏和后台限制如实提示。
- 桌面 Chrome/Safari：逐篇朗读可正常播放，切换栏目不重复播报。
- 新闻生成器更新后 audio.html 不被覆盖，首页入口持续存在。
- 播客阶段：核对音频文件完整性、内容准确性、大小、时长、订阅源及每日成本。
